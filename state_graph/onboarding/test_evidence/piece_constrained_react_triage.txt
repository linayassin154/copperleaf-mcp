Constrained-ReAct gap fix — test evidence
==========================================

CONTEXT
-------
The team plan doc requires Graph 1 (Supplier Onboarding) to have TWO LLM-call
additions: RAG (policy_check.py, already built/verified) AND constrained ReAct
(whitelist only: request-documents, extract-terms, flag-for-review; never
auto-approve). A repo review found intake.py/admin_review.py were both plain
deterministic functions -- constrained ReAct did not exist anywhere in the
graph. This file records the fix: state_graph/onboarding/nodes/react_triage.py,
a new intake_triage node wired between awaiting_documents and terms_extracted.

WHAT WAS ADDED
--------------
- nodes/react_triage.py: an LLM (ChatGoogleGenerativeAI) bound via
  bind_tools() to exactly three LangChain @tool functions: request_documents,
  extract_terms, flag_for_review. No fourth tool exists, so there is no
  "approve" action the model could pick even if it wanted to -- the whitelist
  is enforced structurally by what tools exist, not just by prompt wording.
- graph.py: new node "intake_triage" wired awaiting_documents -> intake_triage
  -> {awaiting_documents | terms_extracted | ticket_open} via a conditional
  edge (route_after_triage). The request_documents branch loops back to
  awaiting_documents -- a genuine cycle, not just a linear branch.
- ticket.py: ticket_open's reason text now distinguishes "flagged by
  constrained-ReAct triage" from the original "zero extracted terms" trigger,
  so an admin reading a ticket can tell which one fired.
- state.py: added triage_decision / triage_reason fields; added "triaged" to
  OnboardingStatus.
